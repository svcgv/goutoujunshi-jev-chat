# Android 统一模型管理与功能级模型选择

## 1. 前置条件与目标

- 仅 Android；暂不修改 macOS 和 Windows。
- 在会话 `01a1215b-09ee-7f03-91f6-1e2574a9114b` 完成后，以其稳定改动为基础实现。
- 将配置统一为：**服务（地址、密钥）→ 多个模型 → 全局接口关联 → 可选功能级生成模型覆盖**。

## 2. 页面与配置行为

- 新增独立“服务与模型”管理页，支持新增、编辑、删除服务，以及手动添加或从兼容服务 `/models` 拉取、搜索、多选导入模型。
- 服务保存名称、类型、地址和密钥，并提供 OpenRouter、TypeSafe、DeepSeek、通义兼容、CLI-Proxy-API／自定义兼容预设。
- 模型保存显示名称、实际模型 ID、调用协议和图片能力。OpenRouter 服务可同时管理 Jev 与聊天模型，但必须分别使用正确协议。
- 原设置页统一为“判断模型、回复模型、视觉模型”，只保存模型引用和可选的接口测试结果。
- 视觉模型只显示已标记支持图片的聊天模型；可从可靠列表元数据填充能力，其余由用户确认。
- 增加“功能模型”分区：发起聊天、结束聊天、问军师分别可选生成模型，默认“跟随全局回复模型”；普通“帮我回复”继续使用全局回复模型。
- 功能覆盖保存模型引用而非复制地址和密钥。全局回复模型变化时，继承项自动跟随；页面明确显示每项实际生效的服务和模型。
- 被引用的服务或模型禁止直接删除；协议、图片能力改变会导致关联失效时也禁止保存。

## 3. 内部接口与调用接入

- 新增内部配置类型：`ServiceConfig`、`ModelConfig`、`InterfaceBindings`、`FeatureModelOverrides` 和解析后的 `ResolvedRoute`。
- 使用带版本号的应用私有配置快照一次性保存；密钥不进入日志、Intent 或错误详情。
- 在现有军师编排层按任务解析生成模型，并将解析结果传入现有判断、生成、候选排序、结构化修复和上下文压缩链路；不得通过临时改写全局 `Prefs` 实现功能覆盖。
- 全局判断为聊天模型时继续使用全局判断模型；Jev 路线下保留当前兼容策略，由功能实际生效的生成模型承担新军师任务分析，并在设置页明确说明。
- 一次用户操作使用同一配置快照；运行中修改配置只影响后续操作。
- 保留 Jev 专用端点、OpenAI 兼容协议和 DeepSeek 官方参数差异；不根据模型名称猜测特殊能力。
- 新配置只使用所属服务的密钥，取消运行时跨接口借用密钥；模型列表请求也不得自动跳转到其他来源。
- 未配置、引用失效或协议不匹配时明确报错，不静默切换模型；仅在用户显式选择“跟随全局”时使用继承。
- 保留该会话已有的对象隔离、取消、安全边界、咨询原文及精简记忆授权行为。

## 4. 旧配置迁移

- 首次升级将旧判断、回复、视觉配置转换为服务、模型和关联；升级后功能覆盖默认留空，继续跟随全局回复模型。
- 先按旧规则计算有效密钥，再写入对应服务，保留原本合法的同源密钥复用效果。
- 只合并地址、凭据和协议均兼容的服务；不同密钥或不同自定义路径不得强制合并。
- 旧视觉模型保留图片能力标记，避免阻断现有 OCR；不将此标记描述为重新验证。
- 迁移成功持久化后才记录完成，重复执行不得生成重复配置；旧字段仅作为迁移依据，不再作为运行时第二配置源。
- 无旧配置时显示待配置状态，不创建看似可用的默认绑定。

## 5. 测试与验收

- 配置测试：一个服务多个模型、跨接口复用、保存重启恢复、服务修改联动、删除保护、视觉能力过滤。
- 覆盖测试：三个功能分别继承或独立选择、全局模型变化只影响继承项、取消覆盖恢复跟随、普通回复不受影响。
- 调用测试：验证各功能最终使用的端点、模型和密钥；覆盖聊天判断与 Jev 兼容路径、修复重试、多轮咨询和请求期间修改配置。
- 迁移测试：Jev、DeepSeek、兼容代理、同源借用密钥、自定义地址、空配置和重复迁移。
- 模型发现测试：成功、空列表、重复 ID、401、404、超时、格式异常及能力元数据；失败不得破坏现有配置。
- 功能回归：无记录开场、三类收尾、多轮咨询、停止联系边界、取消与换对象、视觉 OCR、普通回复及记忆授权。
- 运行 Android 单元测试、Lint 和 Debug 构建，并进行设备或模拟器页面验收；真实服务测试仅在已有凭据时执行，不自动发起计费测试。

**默认边界：**本次不包含桌面端同步、各功能独立判断模型、按对象绑定模型、失败自动切换、每轮临时选择模型或新增 API 协议。
